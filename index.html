    RC Rent ระบบเช่ารถrc_rent

    เว็บแอปเช่ารถแบบ full-stack แยก frontend React กับ REST API ที่เขียนด้วย Express ผู้ใช้ค้นหารถ จอง และดูประวัติการเช่าของตัวเองได้

    โจทย์

    ฝึกสร้างระบบเว็บแบบ full-stack ที่แยก frontend กับ backend ชัดเจน มีระบบสมาชิก สิทธิ์ผู้ดูแล และขั้นตอนการจองที่ต้องเช็กข้อมูลให้ถูกต้องเหมือนระบบเช่ารถจริง

    ผู้ใช้ใช้งานยังไง

    1. สมัครสมาชิกและล็อกอิน หน้าที่ต้องล็อกอินก่อน เช่น การจองและประวัติการเช่า จะพาไปหน้า login อัตโนมัติ
    2. ดูรายการรถ ค้นหาและกรองตามที่ต้องการ แล้วกดเช่า
    3. ดูประวัติการเช่าของตัวเองในหน้า My Rentals และยกเลิกรายการได้
    4. แอดมินเพิ่ม แก้ไข และลบข้อมูลรถได้ ผู้ใช้ทั่วไปทำไม่ได้
    5. สลับภาษาไทย/อังกฤษได้ทั้งแอป

    เบื้องหลังทางเทคนิค

    • Frontend: React 19 + TypeScript + Vite ใช้ React Router และ Context แยกสถานะผู้ใช้ (AuthContext) กับภาษา (i18n)
    • Backend: Express 5 แยก route เป็น auth, cars, rentals และ users เข้ารหัสรหัสผ่านด้วย bcrypt ส่ง JWT ผ่านคุกกี้ httpOnly
    • ฐานข้อมูล MySQL ใช้ stored procedure สำหรับสร้าง ดู และยกเลิกการเช่า ทำให้ logic สำคัญอยู่ที่ฐานข้อมูล
    • ตรวจข้อมูลขาเข้าด้วย express-validator และใช้ middleware adminOnly กันไม่ให้ผู้ใช้ทั่วไปแก้ข้อมูลรถ ใส่ helmet และจำกัด CORS ให้เฉพาะ frontend
    • CI บน GitHub Actions รัน lint, เช็ก format ด้วย Prettier และ build ทุกครั้งที่ push

    Matcha Kon Raeng Feedbackmatcha-kon-raeng-feedback

    เว็บแอปเก็บรีวิวจากลูกค้าร้านมัทฉะคนแรง ลูกค้าสแกน QR บนออเดอร์ ให้ดาวและคอมเมนต์ได้ในไม่กี่วินาที เจ้าของร้านดูภาพรวมได้จากแดชบอร์ด

    โจทย์

    ร้านมัทฉะคนแรงขายผ่านเดลิเวอรี จึงไม่เคยได้คุยกับลูกค้าตรงๆ และไม่รู้ว่าลูกค้าชอบหรือไม่ชอบอะไร รีวิวบนแอปเดลิเวอรีก็มีน้อยและร้านเข้าไปดูรายละเอียดไม่ได้

    ลูกค้าใช้งานยังไง

    1. ร้านแปะ QR code ไว้กับออเดอร์ ลูกค้าสแกนแล้วเข้าหน้ารีวิวได้ทันที ไม่ต้องลงแอปหรือสมัครสมาชิก
    2. กดให้ 1–5 ดาว ใส่ชื่อหรือไม่ใส่ก็ได้ แล้วพิมพ์ความเห็นสั้นๆ
    3. รีวิวขึ้นในหน้าเดียวกันทันที ลูกค้าคนอื่นเห็นได้
    4. เจ้าของร้านเข้า /admin ใส่ PIN แล้วดูคะแนนเฉลี่ย กราฟกระจายคะแนน และรีวิวทั้งหมดเรียงจากใหม่ไปเก่า

    เบื้องหลังทางเทคนิค

    • Express API สองเส้นหลัก คือ GET และ POST /api/reviews ตรวจว่าคะแนนเป็นจำนวนเต็ม 1–5 และตัดชื่อไว้ที่ 60 ตัวอักษร ความเห็นที่ 500 ตัวอักษร
    • ตาราง reviews ใน PostgreSQL มี CHECK constraint บังคับช่วงคะแนนซ้ำอีกชั้นที่ฐานข้อมูล ใช้ parameterized query กัน SQL injection
    • กันสแปมด้วย cooldown 8 วินาทีต่อ IP อ่าน IP จริงจาก X-Forwarded-For เพราะแอปอยู่หลัง proxy ของ Railway
    • หน้า admin ใช้คุกกี้แบบ signed + httpOnly + sameSite อายุ 12 ชั่วโมง ไม่ต้องมีระบบผู้ใช้เต็มรูปแบบ
    • หน้ารีวิวเปิดได้เฉพาะลิงก์ที่มาจาก QR (?qr=1) กันคนนอกที่ไม่ได้สั่งจริงเข้ามารีวิว

    Astrohouse Cafe เมนูดิจิทัลAstroHouse

    สมุดเมนูดิจิทัลของคาเฟ่ที่พลิกหน้าได้เหมือนเมนูจริง ลูกค้าเลือกอาหารใส่ตะกร้า เขียนหมายเหตุ แล้วส่งออเดอร์เป็นข้อความ LINE ไปที่ร้าน

    โจทย์

    คาเฟ่อยากได้เมนูที่ดูหรูเหมือนสมุดเมนูจริง ใช้ได้ทั้งบนแท็บเล็ตในร้านและบนมือถือลูกค้า และอยากให้ลูกค้าสั่งอาหารได้เองโดยไม่ต้องรอพนักงานมาจด

    ลูกค้าใช้งานยังไง

    1. เปิดเมนูบนแท็บเล็ตในร้าน หรือสแกน QR ในหน้าแรกเพื่อเปิดบนมือถือตัวเอง
    2. ปัดพลิกหน้าเหมือนเปิดสมุดจริง เมนูแบ่งเป็นเครื่องดื่ม อาหาร และของหวาน รวมหลายสิบหมวดย่อย ตั้งแต่อาหารเช้า สเต๊ก ญี่ปุ่น ไปจนถึงอาหารไทย
    3. กดเพิ่มเมนูลงตะกร้า เลือกตัวเลือกย่อยได้ (เช่น แบบทะเล) ปรับจำนวน และเขียนหมายเหตุรายจาน เช่น ไม่ใส่ผัก เผ็ดน้อย
    4. กดส่งออเดอร์ แอปสร้างข้อความสรุปรายการและราคารวม แล้วเปิด LINE Official Account ของร้านพร้อมข้อความนั้นให้กดส่งได้เลย

    เบื้องหลังทางเทคนิค

    • เขียนด้วย Flutter แล้ว build เป็นเว็บ ใช้ package page_flip ทำเอฟเฟกต์พลิกหน้า และ Google Fonts (Cinzel, Playfair Display, Lora) ให้ได้อารมณ์เมนูพรีเมียม
    • CartService ใช้ ChangeNotifier จัดการ state ของตะกร้า แยกรายการตามชื่อจานรวมกับตัวเลือก ถ้าสั่งซ้ำจะเพิ่มจำนวนแทนการเพิ่มบรรทัดใหม่
    • ส่งออเดอร์ผ่าน deep link line://oaMessage และมีลิงก์ line.me เป็นทางสำรองเมื่อเครื่องไม่ได้ลง LINE
    • ข้อมูลเมนูและราคาอยู่ในไฟล์เดียว (menu_data.dart) ร้านแก้ราคาหรือเพิ่มเมนูได้ง่าย
    • ทุกครั้งที่ push, GitHub Actions จะ build และ deploy ขึ้น GitHub Pages ให้อัตโนมัติ ใช้งานฟรีและไม่มีวันหมดอายุ

    ระบบประเมินผู้สูงอายุที่มีภาวะพึ่งพิงProject_finish

    เว็บแอปที่เปลี่ยนแบบประเมินสุขภาพผู้สูงอายุจากกระดาษเป็นดิจิทัล ให้เจ้าหน้าที่สาธารณสุขลงพื้นที่เก็บข้อมูล และให้แพทย์สั่งแผนการดูแลต่อได้ในระบบเดียว

    โจทย์

    เจ้าหน้าที่สาธารณสุขต้องลงพื้นที่ประเมินผู้สูงอายุที่มีภาวะพึ่งพิงด้วยแบบฟอร์มกระดาษ ข้อมูลกระจัดกระจาย สรุปสถิติยาก และแพทย์ติดตามผลหรือสั่งการดูแลต่อได้ช้า

    ระบบทำงานยังไง

    1. เจ้าหน้าที่ (Staff) ลงทะเบียนผู้สูงอายุพร้อมที่อยู่และพิกัดบ้านบนแผนที่
    2. ทำแบบประเมินมาตรฐาน 3 ชุด: Barthel ADL (10 ด้าน), Care Giver (ข้อมูลผู้ดูแลกว่า 37 มิติ) และ TAI ระบบคิดคะแนนและจัดกลุ่มติดสังคม ติดบ้าน หรือติดเตียงให้อัตโนมัติ
    3. แพทย์ (Doctor) ดูประวัติรายบุคคล แล้วออกคำสั่งการดูแล (Care Instruction) ส่งให้เจ้าหน้าที่
    4. เจ้าหน้าที่กดยืนยันรับทราบ สถานะเปลี่ยนจากรอยืนยันเป็นรับทราบแล้ว ทุกการกระทำถูกบันทึกใน audit log
    5. ผู้ดูแลระบบ (Admin) จัดการผู้ใช้ ข่าวประกาศ และแบนเนอร์ ส่วนผู้บริหารดูแดชบอร์ดสถิติตามช่วงวัยและกลุ่มสุขภาพ แล้วออกรายงานเป็น PDF

    เบื้องหลังทางเทคนิค

    • Laravel 10 แบบ MVC มี middleware แยกสิทธิ์ตามบทบาท (IsAdmin, IsStaff, IsDoctor) และ middleware เพิ่ม security header
    • บันทึกข้อมูลหลายตารางใน DB::transaction() ถ้าพังกลางทางจะไม่เหลือข้อมูลครึ่งๆ กลางๆ และใช้ Soft Delete กับข้อมูลทางการแพทย์ เพื่อไม่ให้ประวัติหายถาวร
    • ใช้ Eager Loading แก้ปัญหา N+1 query และ paginate ทุกตารางใหญ่แทนการดึงข้อมูลทั้งหมด
    • สร้าง PDF ด้วย mPDF แสดงตารางด้วย DataTables และเขียนข่าวด้วย Quill Editor
    • มี Dockerfile และคู่มือ deploy 4 แบบ: Railway, Docker, VPS และ cPanel

    บั๊กที่เจอและแก้ก่อน deploy

    • ฟอร์มแบบหลายขั้นตอนกดไปขั้นถัดไปไม่ได้ เพราะ JavaScript อ้างอิง element ID ที่ไม่มีอยู่จริง
    • บั๊กที่เกิดเฉพาะบน Linux: Windows ไม่สนตัวพิมพ์เล็ก-ใหญ่ของชื่อไฟล์ แต่ Linux สน จึงเขียนสคริปต์ไล่ตรวจชื่อ view ทั้งระบบในครั้งเดียว
    • session หมดอายุแล้วขึ้น error 500 แทนที่จะพาไปหน้า login เพราะ route login ไม่ได้ตั้งชื่อไว้
    • ทุกการแก้ยืนยันด้วยการ compile view ทั้งระบบ และทดสอบผ่าน HTTP จริงใน Docker
